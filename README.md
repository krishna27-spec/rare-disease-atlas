# Rare Disease Atlas

An evidence-backed knowledge graph and web app for ~22 neuronopathic lysosomal storage diseases (Sanfilippo/MPS III, the NCLs, Niemann-Pick C, GM1/GM2, MLD, Krabbe, alpha-mannosidosis, mucolipidosis IV, plus MPS I/II for contrast). Built for the Hack-Nation "AI Atlas for the World's Rare Diseases" challenge.

> **Research exploration tool. Not medical advice.** Always confirm with clinicians and researchers.

## What it does: the "Maria" journey
Maria leads a patient group for **MPS IIIC (gene HGSNAT)**. The app answers three questions:

1. **Who shares our disease characteristics?** Search "Sanfilippo C"; the app ranks the most similar diseases (MPS IIIA/IIIB first), with *why* (shared heparan sulfate degradation pathway, shared informative symptoms) and *what differs* (different causal genes, symptoms listed for only one).
2. **What useful work already exists?** Natural history studies, registries and trials, investigators who work across several of these diseases, and patient organisations.
3. **What should we do together next?** 1-3 plain-language next steps. Code finds candidate actions in the graph; the LLM may only reword them and must cite edge IDs, and every sentence is checked in code to cite real edges.

When nothing is supported (for example a search for a disease outside our scope) the app says so, lists what was searched and what evidence is missing. A **10× tab** compares building a natural history study for MPS IIIC from scratch with reusing what sister diseases built, using real durations from ClinicalTrials.gov and stating no invented savings.

## Architecture
```
sources (MONDO, HPO, Orphadata, HGNC, Reactome, ClinVar, PubMed, ClinicalTrials.gov, NIH RePORTER, hand-curated patient orgs)
   -> src/etl/*        download once into data/raw, cache API answers in data/cache
   -> src/graph/*      build nodes + edges, similarity + Louvain clusters, connections tables
   -> data/graph/      nodes.parquet, edges.parquet, neighbours/shared_people/cluster_assets tables, STATS.md
   -> app/app.py       Streamlit reads only these files
LLM (gpt-oss-20b via an OpenAI-compatible API, Groq): (a) offline extraction from abstracts, (b) live plain-language wording of cited steps.
```
The graph is built offline; the app never calls an LLM to build it, and still works (showing the cited candidate list) if the LLM is down.

## Evidence model
Every edge (`data/graph/edges.parquet`) carries `source`, `source_record`, `source_url`, `retrieved` date, `confidence`, and one of three evidence types:

| type | meaning | colour in app |
|---|---|---|
| `curated` | taken from a database file or API | blue |
| `text_mined` | an LLM read a PubMed abstract; exact sentence stored | orange |
| `inferred` | our code computed it (similarity); `method` filled | grey |

**Confidence rules:** Orphadata "disease-causing germline mutation" 0.95 (0.85 via a parent disease); HPO annotation 0.9 (lower if "occasional"); trials/investigators 0.8-0.9; text-mined 0.7 "stated", 0.5 "suggested"; inferred = the similarity score.

**Quote check:** a text-mined fact is kept only if its quoted sentence appears word for word in the abstract (whitespace/case ignored), and its names resolve to stable IDs already in the graph (MONDO diseases restricted to the paper's own diseases, HGNC genes incl. aliases, HP phenotypes). Everything dropped is counted by reason in `data/graph/STATS.md`.

Stable IDs: MONDO, HGNC symbol, HP, Reactome, `PMID:`, `NCT`, NIH project numbers.

## Numbers
See [`data/graph/STATS.md`](data/graph/STATS.md) (regenerated by the build). It reports node/edge counts per type and predicate, and the text-mining funnel (abstracts read, facts kept, dropped for no quote / unresolved / out of scope).

## Rebuild the dataset
```bash
uv sync
cp .env.example .env        # fill in LLM_* and NCBI_* values
uv run python -m src.graph.build        # ~20 s with warm caches; first run downloads data
uv run streamlit run app/app.py
```
`build` runs: download, biology, research, timelines, similarity, abstract filter, text_mined, connections, stats. Extraction is separate because it is slow and uses an LLM:
```bash
uv run python -m src.etl.filter_abstracts     # keep on-topic abstracts
uv run python -m src.extract --workers 1      # resumable; Groq free tier ~4 abstracts/min
uv run python -m src.graph.build              # fold the new facts into the graph
```

## Limitations (honest)
- 22 diseases only. OMIM is not used. Patient organisations are hand-curated (5 so far; checked 2026-10-04; scope of one not fully verified).
- Only a small share of the filtered abstracts has been read by the LLM (Groq free tier is slow); see STATS.md for the exact number. Text-mined edges are therefore sparse (they supplement the curated graph).
- Extraction records "stated"/"suggested" but not negation, so contradiction detection finds 0 and says so.
- Similarity uses HPO annotations, which are uneven across diseases.
- The question of whether cross-correction approaches used for MPS IIIA transfer to MPS IIIC (HGSNAT is a membrane enzyme) is **not** claimed: no cited source is in the graph. Future work.
- Time to *set up* a natural history study has no cited figure, so the 10× tab states none.

## Scale-up path
`notebooks/extract_molab.py` runs the same extraction on a free molab GPU (gpt-oss-20b via vLLM) for all abstracts (written but not yet run); add more diseases; add a Claude second-reviewer pass to set `reviewer_verdict` and the +0.15 confidence rule; add negation extraction for real contradictions.
